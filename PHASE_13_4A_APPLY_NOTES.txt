TUPAD REPORTING SYSTEM
PHASE 13.4A - UI & ERROR-STATE CLEANUP OVERLAY

PURPOSE
-------
This is a NON-DESTRUCTIVE overlay. It intentionally contains only NEW files so it will not overwrite the newer Phase 10-13 views/controllers in your working project.

COPY / EXTRACT
--------------
Extract this ZIP into the root of your current tupad-reporting-system project.
Allow Windows to merge the resources/ folders.

FILES ADDED
-----------
resources/views/layouts/error.blade.php
resources/views/errors/403.blade.php
resources/views/errors/404.blade.php
resources/views/errors/419.blade.php
resources/views/errors/500.blade.php
resources/views/components/page-alerts.blade.php
resources/views/components/empty-state.blade.php

PAGE ALERT INTEGRATION
----------------------
In high-use pages, add this immediately below the page heading/header:

    <x-page-alerts />

Recommended pages:
- resources/views/projects/show.blade.php
- resources/views/projects/create.blade.php
- resources/views/project-drafts/create.blade.php
- resources/views/project-drafts/edit.blade.php
- resources/views/project-drafts/show.blade.php
- resources/views/projects/beneficiaries/index.blade.php
- resources/views/reports/index.blade.php

If a page already has a page-level @if(session('success')) or @if($errors->any()) block, remove that old page-level block after adding <x-page-alerts /> to avoid duplicate alerts. Keep field-specific @error(...) messages.

EMPTY STATE USAGE
-----------------
Inside a table empty row:

    <tr>
        <td colspan="8">
            <x-empty-state
                title="No projects found"
                message="No project records match the current filters."
            />
        </td>
    </tr>

TEST CUSTOM ERROR PAGES
-----------------------
404 while logged in:
    http://127.0.0.1:8000/projects/999999999

403 as GIP:
    http://127.0.0.1:8000/reports

403 as Focal:
    http://127.0.0.1:8000/projects/create

419:
    Use an expired CSRF/session form submission.

500:
    Laravel's debug exception screen takes precedence when APP_DEBUG=true.
    Temporarily set APP_DEBUG=false only when testing the production-style 500 page, then restore development settings.

---------
