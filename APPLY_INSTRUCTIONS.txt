TUPAD REPORTING SYSTEM
MAJOR REVISION — PHASE 4
SUBMISSION OF POST-DOCUMENTARY REQUIREMENTS

DOCUMENT BASIS
--------------
Revised TUPAD 360 workflow:

Submission of Post-Documentary Requirements (TC Account)
1. Date Received
2. Attachments Received
3. Date Forwarded to IMSD
4. Save -> Auto-update Status: For Payment

IMPLEMENTED
-----------
The old single "Document Type + optional Attachment" form is replaced in the
normal UI by one complete submission form containing exactly the revised core
inputs:

- Date Received
- Attachments Received
- Date Forwarded to IMSD
- optional Remarks

ATTACHMENTS RECEIVED
--------------------
Multiple files can be selected in one submission.

Supported:
PDF
JPG/JPEG
PNG
DOC/DOCX
XLS/XLSX

Maximum:
10 MB per file
20 files per submission

Each selected file is stored as its own project_post_documents row so the
existing private secure-download architecture remains intact.

The visible document label becomes the original attachment filename.

AUTO-UPDATE STATUS
------------------
All three official inputs are required.

A successful save therefore means the submission is complete and immediately
updates:

FOR SUBMISSION OF POST-DOCS
-> FOR PAYMENT

There is no separate manual transition.

DATE RULE
---------
Date Forwarded to IMSD cannot be earlier than Date Received.

ATOMIC SAVE
-----------
The database work is wrapped in a transaction.

If an exception occurs after files have been written, newly stored files are
deleted so the request does not leave orphan upload files.

BACKWARD COMPATIBILITY
----------------------
The controller still accepts the older single-file payload:

document_type
attachment

This is retained for old integrations/tests.

The revised UI uses:

attachments[]

with multiple file selection.

NO DATABASE MIGRATION REQUIRED.
