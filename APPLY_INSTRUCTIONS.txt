NEW RELEASE-VERIFIER COVERAGE
-----------------------------
The existing `php artisan tupad:release-verify` command now also validates:

1. Phase 12 schema availability
   - project_implementations
   - project_acp_payments
   - project_acp_check_releases
   - project_acp_check_release_attachments
   - project_acp_liquidations
   - project_acp_liquidation_attachments

2. Through ACP payment integrity
   - ACP payment records may belong only to Through ACP projects.
   - ACP payment amount must equal the approved project total_project_cost.

3. Through ACP check-release integrity
   - Check release may belong only to Through ACP projects.
   - A payment record must exist.
   - Released amount must match the official ACP payment amount.
   - Check date cannot precede payment date.
   - Released date cannot precede check date.

4. Through ACP implementation integrity
   - An ACP implementation period with a record must have a check release.
   - Start date cannot precede check release date.
   - End date cannot precede start date.

5. Through ACP liquidation integrity
   - Liquidation rows may belong only to Through ACP projects.
   - Liquidation amounts must be positive.
   - Check release and implementation records must exist when liquidation exists.
   - Liquidation date cannot precede implementation end date.
   - Total liquidation cannot exceed the released check amount.

6. Cross-mode workflow integrity
   - Direct Administration cannot use ACP-only statuses:
       For Release of Check to Proponent
       For Liquidation
       Partially Liquidated
   - Through ACP cannot use the DA-only For Submission of Post-Docs status.

LEGACY-SAFETY NOTE
------------------
The verifier does NOT automatically fail every historical Through ACP project
simply because it predates the new Phase 12B/12C ACP transaction tables.
It blocks contradictory ACP transaction data when those records exist and blocks
cross-mode workflow states. It remains non-destructive and performs no automatic
repair or migration of legacy records.

FULL RELEASE VERIFICATION
-------------------------
php artisan test
php artisan tupad:release-verify
npm run build

Before an actual production deployment, run the production-enforced verifier in
an environment configured with the intended production values:

php artisan tupad:release-verify --production

The --production form intentionally checks production requirements including:
- APP_DEBUG=false
- persistent APP_KEY
- MySQL as the configured database
- no active account still using the development password "password"

Do not interpret a --production failure on an intentionally development-configured
local environment as an application regression; correct the deployment
configuration and rerun it in the release environment.
