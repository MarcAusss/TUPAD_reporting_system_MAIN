TUPAD Major Revision Phase 13E Hotfix 02
Release Verifier Coordinator Diagnostic Output Contract

PURPOSE
The Phase 13E release verifier already detects active TUPAD Coordinators that are unassigned or assigned to inactive provinces. Laravel's console test output matcher can receive long styled error messages in wrapped chunks, causing the full username substring to be split and making the two username assertions fail even though the verifier correctly blocks release.

THIS HOTFIX
- Keeps the existing blocking failure messages and exit codes unchanged.
- Keeps one blocking issue per integrity rule (does not inflate the blocking-issue count per user).
- Prints each affected Coordinator username on a short explicit diagnostic line:
  Affected Coordinator: <username>
- No authorization, province scoping, database, seeder, workflow, or UI logic changes.

REPLACED FILE
app/Console/Commands/VerifyReleaseReadiness.php

APPLY
Extract this ZIP over the Laravel project root and allow the file to be replaced.

RUN
php artisan optimize:clear
php artisan test tests/Feature/MajorRevisionPhase13EAuthenticationProvinceSecurityReleaseVerificationTest.php

Then:
php artisan test
php artisan tupad:release-verify
npm run build
