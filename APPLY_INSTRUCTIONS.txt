TUPAD Reporting System
Major Revision Phase 10 - Hotfix 01
Executive Dashboard / Phase 9 Report Regression Fix

PURPOSE
-------
This hotfix addresses the exact failures reported after applying the Phase 10 overlay:

1. Laravel throws:
   Method Illuminate\Validation\Validator::validateProhibitedWith does not exist.

   Cause:
   The project used the unsupported validation rule "prohibited_with" in both the
   Phase 10 ExecutiveDashboardRequest and the existing Phase 9 ReportController.

   Fix:
   The unsupported rule is removed and quarter/month mutual exclusivity is enforced
   in an explicit validator after-hook. Existing required_with:fiscal_year behavior is
   preserved.

2. Phase 9 reports throw:
   Class "CarbonCarbonImmutable" not found.

   Cause:
   resources/views/reports/index.blade.php contains a malformed class reference.

   Fix:
   It now uses the correct fully qualified class:
   \Carbon\CarbonImmutable

FILES TO REPLACE
----------------
1. app/Http/Requests/ExecutiveDashboardRequest.php
2. app/Http/Controllers/ReportController.php
3. resources/views/reports/index.blade.php

ADDED FILES
-----------
None.

MIGRATIONS
----------
None added. Do NOT run migrate:fresh.

DEPENDENCIES
------------
No Composer dependencies added.
No npm dependencies added.
No npm build is required for this hotfix.

APPLY
-----
From this hotfix overlay, copy the three replacement files into the matching paths
inside your latest TUPAD Reporting System project and allow them to replace the
existing files.

Then run from the project root:

    php artisan optimize:clear

The optimize clear is important because the Phase 9 failure occurred inside a
compiled Blade view under storage/framework/views.
